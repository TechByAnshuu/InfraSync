1 Getting the Project Files into Your Ubuntu VM

Choose either Method A (Git Clone) or Method B (SCP / Windows Terminal) to transfer your workspace into Ubuntu:

Method A: Via GitHub (Recommended)

Inside your Windows project folder C:\Users\Ansh Mishra\Documents\InfraSync, push to GitHub:

git init
git add .
git commit -m "Initial commit of InfraSync pipeline"
git branch -M main
git remote add origin https://github.com/<your-username>/InfraSync.git
git push -u origin main

Then inside your Ubuntu VM terminal:

git clone https://github.com/<your-username>/InfraSync.git ~/InfraSync
cd ~/InfraSync

Method B: Direct Copy via SCP from Windows PowerShell

1. Find your Ubuntu VM IP by running ip a in the VM (look for the IP on ens33 or eth0, e.g. 192.168.120.130).

2. If SSH is not yet active on Ubuntu, run inside VM:

sudo apt update && sudo apt install -y openssh-server && sudo systemctl enable --now ssh

3. In Windows PowerShell (on your host machine), run:

scp -r "C:\Users\Ansh Mishra\Documents\InfraSync" <ubuntu-username>@<VM-IP>:~/InfraSync

2 Installing Required DevOps Tools in Ubuntu

Open the terminal inside your Ubuntu VM (or SSH into it) and execute these steps:

Step 2.1: Update System Packages

sudo apt update && sudo apt upgrade -y

Step 2.2: Install Docker Engine & Configure Permissions

sudo apt install -y docker.io
sudo systemctl enable --now docker
sudo usermod -aG docker $USER
Crucial Step: Activate the new docker group without rebooting:
newgrp docker
Verify with: docker run --rm hello-world (must succeed without sudo).

Step 2.3: Install HashiCorp Terraform

sudo apt install -y gnupg software-properties-common curl wget
wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg
echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list
sudo apt update && sudo apt install -y terraform
terraform -version

Step 2.4: Install Ansible & Git

sudo apt install -y ansible git
ansible --version
VMware Snapshot Tip: At this point, shut down or pause the VM and take a VMware snapshot named: 01-tools-installed. If anything breaks later, you can restore to this clean baseline in seconds.

3 Deploying Infrastructure with Terraform

Step 3.1: Navigate to Terraform Directory

cd ~/InfraSync/terraform

Step 3.2: Initialize and Apply Configuration

terraform init
terraform plan
terraform apply -auto-approve

Terraform will download the Docker provider, pull nginx:stable and haproxy:lts, create the lab-net network, generate custom web pages using web.html.tpl, and start all 4 containers.

Step 3.3: Verify Running Containers

docker ps

Confirm the output displays four healthy containers:

  • haproxy - Ports: 0.0.0.0:8080->80, 0.0.0.0:8404->8404
  • web1 - Port: 0.0.0.0:8081->80
  • web2 - Port: 0.0.0.0:8082->80
  • web3 - Port: 0.0.0.0:8083->80

Step 3.4: Verify Direct Access & Round-Robin Load Balancing

# Test each backend directly
curl -s localhost:8081 | grep "<h1>"
curl -s localhost:8082 | grep "<h1>"
curl -s localhost:8083 | grep "<h1>"

# Test round-robin distribution through HAProxy
for i in {1..6}; do curl -s localhost:8080 | grep "<h1>"; done

Expected Output: The curl loop will output web1 → web2 → web3 → web1 → web2 → web3.

Step 3.5: Access from Windows Host Browser

On your Windows machine, open Google Chrome or Edge and browse to:

  • Web Application: http://<VM-IP>:8080 (Refresh repeatedly; watch the active container and color cycle between web1, web2, and web3).
  • HAProxy Live Statistics: http://<VM-IP>:8404/stats (Displays backend status table with green rows).

4 Deploying Monitoring & Auto-Remediation with Ansible

Step 4.1: Create Nagios Web Authentication User

Nagios Core web UI requires an Apache digest user. Run this one-time command:

sudo htdigest -c /etc/nagios4/htdigest.users Nagios4 nagiosadmin

When prompted, enter your preferred password (e.g., admin123).

Step 4.2: Execute Ansible Playbook

cd ~/InfraSync/ansible
ansible-playbook -i inventory.ini playbook.yml --ask-become-pass

Enter your Ubuntu user password when prompted for become pass.

Step 4.3: Validate Nagios Configuration

sudo /usr/sbin/nagios4 -v /etc/nagios4/nagios4.cfg

Check the bottom of output: Total Warnings: 0 and Total Errors: 0.

Step 4.4: Verify Nagios Dashboard in Browser

In your Windows browser, navigate to: http://<VM-IP>/nagios4

Login with user nagiosadmin and your password. Click on Current Status → Services.

You should see 4 active services in OK (Green) state:

  • Backend web1 (port 8081)
  • Backend web2 (port 8082)
  • Backend web3 (port 8083)
  • HAProxy Load Balancer (port 8080)

6 How Auto-Remediation Works (For Viva & Demo)

During the viva or lab evaluation, follow this demonstration sequence:

  1. Demonstrate Failover First (TC06): 
    sudo rm -f /etc/nagios4/remediation.enabled
docker stop web1
# Run continuous traffic in background:
while true; do curl -s localhost:8080 | grep "<h1>"; sleep 1; done
    Show the teacher that only web2 and web3 respond. The website never goes down! Nagios shows web1 as CRITICAL.
  2. Demonstrate Self-Healing Auto-Remediation (TC07): 
    sudo touch /etc/nagios4/remediation.enabled
docker stop web2
# Watch the remediation logs live:
journalctl -t nagios-remediation -f
    Explain to the examiner:
    • Nagios retries 3 times (SOFT state) to prevent false alerts.
    • On 3rd failed attempt, state becomes HARD CRITICAL.
    • Nagios calls /usr/local/bin/restart_container.sh CRITICAL HARD web2.
    • The script checks the flag file and whitelist, then executes sudo docker start web2.
    • docker ps shows web2 running again, and Nagios returns to OK.

7 Common Troubleshooting & Fixes in VMware

Issue Cause Resolution
Cannot open VM IP from Windows browser Ubuntu firewall (UFW) blocking ports or wrong network adapter. Run sudo ufw disable inside VM. Ensure VMware network adapter is set to NAT or Bridged.
Docker permission denied Current user not refreshed in docker group. Run sudo usermod -aG docker $USER && newgrp docker.
Nagios 404 Not Found Apache CGI module or config not loaded. Run sudo a2enmod cgi auth_digest && sudo systemctl restart apache2.
Nagios config validation error Typo or missing directive in /etc/nagios4/conf.d/lab.cfg. Run sudo nagios4 -v /etc/nagios4/nagios4.cfg; read the exact line number reported and fix in ansible/templates/lab.cfg.j2.
Remediation does not restart container Flag file missing or nagios user lacks sudo permission. Check ls -l /etc/nagios4/remediation.enabled. Test sudo permission directly: sudo -u nagios sudo -n /usr/bin/docker start web1.
