Full Production Execution Roadmap

Execute these verified commands inside your Ubuntu 24.04 VMware Virtual Machine. Each stage aligns with your INT333 Project Build Guide.

STAGE 1 Virtual Machine & Prerequisite Toolchain Setup
1. Update Ubuntu 24.04 packages and verify VM IP address:
sudo apt update && sudo apt upgrade -y && ip a
2. Install Docker Engine and configure non-root user permissions:
sudo apt install -y docker.io && sudo systemctl enable --now docker && sudo usermod -aG docker $USER
3. Install HashiCorp Terraform official APT repo:
sudo apt install -y gnupg software-properties-common curl wget && wget -O- https://apt.releases.hashicorp.com/gpg | sudo gpg --dearmor -o /usr/share/keyrings/hashicorp-archive-keyring.gpg && echo "deb [signed-by=/usr/share/keyrings/hashicorp-archive-keyring.gpg] https://apt.releases.hashicorp.com $(lsb_release -cs) main" | sudo tee /etc/apt/sources.list.d/hashicorp.list && sudo apt update && sudo apt install -y terraform
4. Install Ansible Core:
sudo apt install -y ansible git
STAGE 2 Terraform Provisioning (Docker Network, 3 Nginx Nodes, HAProxy)
Navigate to terraform folder and deploy infrastructure declaratively:
cd ~/devops-project/terraform && terraform init && terraform plan && terraform apply -auto-approve
Verify containers and round-robin load distribution:
docker ps && for i in {1..6}; do curl -s localhost:8080 | grep "<h1>"; done
STAGE 3 Nagios Core & Auto-Remediation Deployment via Ansible
Create Nagios web credentials (one-time setup for browser login):
sudo htdigest -c /etc/nagios4/htdigest.users Nagios4 nagiosadmin
Execute the Ansible automation playbook:
cd ~/devops-project/ansible && ansible-playbook -i inventory.ini playbook.yml --ask-become-pass
Validate Nagios configuration syntax:
sudo /usr/sbin/nagios4 -v /etc/nagios4/nagios.cfg
STAGE 4 Auto-Remediation Verification & Live Demonstation
Test manual failover (remediation disabled):
sudo rm -f /etc/nagios4/remediation.enabled && docker stop web1
Test self-healing auto-remediation (remediation enabled):
sudo touch /etc/nagios4/remediation.enabled && docker stop web2 && journalctl -t nagios-remediation -f

Viva Examination High-Frequency Questions & Model Answers

Master these core concepts to ace your project evaluation with examiners and professors.

Q1: What is the fundamental difference between Terraform and Ansible?
Terraform is an Infrastructure as Code (IaC) tool designed to provision foundational infrastructure declaratively (networks, virtual containers, VMs). Ansible is a configuration management tool focused on configuring existing machines, installing software packages, configuring services, and deploying daemon scripts.
Q2: What does Idempotency mean in DevOps?
Idempotency guarantees that running an operation multiple times produces the exact same end state without duplicating resources or introducing side effects. If the declared configuration matches the live system, Terraform plans 0 changes and Ansible reports changed=0.
Q3: Explain SOFT vs HARD state in Nagios Core.
When a service check fails, it enters a SOFT state and Nagios retries checking at intervals up to max_check_attempts (e.g. 3 times) to prevent false alarms due to transient network hiccups. Once attempts are exhausted, the failure becomes a HARD state, triggering notifications and our Event Handler.
Q4: Why are sudo permissions restricted to specific docker start commands?
Granting the nagios system user full Docker or sudo privileges is equivalent to granting root compromise access (Docker daemon socket escape). Under the Principle of Least Privilege, we only permit /usr/bin/docker start web1|web2|web3 in /etc/sudoers.d/nagios-docker.
Q5: What is the role of resolvers docker in haproxy.cfg?
When a Docker container is destroyed and recreated or restarted, Docker's internal embedded DNS (127.0.0.11:53) may assign it a different IP address. The HAProxy resolvers docker block enables dynamic runtime re-resolution so HAProxy never gets stuck pointing to stale IPs.
Q6: Why did we use Nagios instead of Prometheus/Grafana?
The INT333 syllabus explicitly covers Nagios Core, active plugin architecture, and event handling hooks. Prometheus is pull-based metric time-series monitoring, whereas Nagios is event-driven status verification with native support for immediate remediation hooks.
